# What Capri 0.7.8 teaches Kiki (2026-11-01)

Capri (`lachydotmcg/capri-desktop`, noncommercial licence: ideas only, no code
or text copied) shipped version 0.7.8 on 2026-10-31. Capri now ships its own
llama.cpp engine with Gemma 4 E4B as the default model, which is the setup
Kiki chose the same day. Read from the source, not run.

## How Capri runs Gemma

| | Capri 0.7.8 | Kiki's plan |
| --- | --- | --- |
| Engine | llama.cpp release `b11669`, the **Windows Vulkan build** (32 MB zip), pinned by SHA-256 | llama.cpp server; build not yet chosen |
| Model file | `ggml-org/gemma-4-E4B-it-GGUF`, `gemma-4-E4B-it-Q4_0.gguf` (4.6 GB) at a pinned revision and SHA-256 | Gemma 4 E4B Q4_0 (QAT), plus the v2 adapter |
| Image reader | a separate `mmproj` file (Q8_0, 560 MB), downloaded and loaded only when wanted (`--mmproj`) | image reader as a setting, off by default: the same split |
| Hardware fit | E4B if VRAM >= 7 GB and RAM >= 12 GB; else E2B if RAM >= 7 GB or VRAM >= 4 GB; else Qwen3 4B | hardware check at first launch (stage 10) |
| Context | 4K, or 8K when long chat memory is on; one size per server start | one size per model (model profile) |

Server flags Capri uses: `-c <window> -np 1 --jinja --reasoning off --no-webui
--sleep-idle-seconds 900 --log-disable -t/-tb <min(4, cores/2)> -b 256 -ub 128
--poll 0 --poll-batch 0`, bound to `127.0.0.1` on a free port.

## What Kiki should adopt

- **`--sleep-idle-seconds`:** llama.cpp's server unloads the model by itself
  after idle time. Kiki's "keep loaded" setting (30 minutes) maps to
  `--sleep-idle-seconds 1800`; no unloading code of our own.
- **Being a good neighbour on the owner's PC:** `--poll 0 --poll-batch 0` (no
  busy-waiting CPU threads), at most four threads, the server at below-normal
  process priority, and a Windows job object so the server dies with Kiki.
  These match the "alongside a browser and work software" requirement.
- **Small batches** (`-b 256 -ub 128`): less memory during prompt reading, at
  some speed cost; measure on the GTX 1080 before choosing.
- **A CPU fallback:** if the graphics driver crashes the server or garbles
  replies, restart on the CPU (`--device none -ngl 0`) and remember it.
- **One slot** (`-np 1`) and `--reasoning off` with `--jinja`, matching the
  model profile (thinking off).
- **Pinned downloads** (engine zip and model files by SHA-256): already Kiki's
  plan for the installer.
- **Gemma output clean-up:** strip `<|channel>thought ... <channel|>` if it
  leaks into content, and read Gemma's own call format when it writes a tool
  call as text (`call:name{key:<|"|>value<|"|>}`); both are already in the
  model profile's clean-up list.

## What Kiki does differently

- **The prompt-cache cap.** Capri passes no `--cache-ram`, so its server's
  prompt cache may grow to 8 GB (`2026-11-01-ollama-prompt-cache.md`). Kiki
  passes `--cache-ram 256`.
- **The adapter.** Capri runs plain Gemma; Kiki loads the v2 adapter
  (`--lora ... --lora-init-without-apply`) and switches it per message.

## To test before choosing

- **Vulkan or CUDA build** on the GTX 1080: Vulkan is one small download that
  works on NVIDIA, AMD, and Intel; CUDA may be faster on NVIDIA but adds
  hundreds of MB. Measure reply speed and memory on the owner's PC.
- **Which Q4_0 file the adapter is applied to.** The trainer's adapter check
  converts Google's unquantized QAT checkpoint itself; if Kiki ships
  `ggml-org`'s Q4_0 file instead, run the adapter check against that file.

## Ideas for the owner

- **Notes in an Obsidian vault** (a community contribution to Capri): her
